### Task 6: The “Invalid frame dimension (negative or non-finite)” warning

This is a root-cause task; use the systematic-debugging approach. The warning has shown up about 8 times per full UI run since plan 1. It's a SwiftUI runtime issue, logged when a `frame` or `size` gets a negative or non-finite value.

- [ ] **Step 1: Reproduce and locate.**
  - Run `testNestedLevelFromMenu` and `testNestedLevelFixFromDefaults`, which both log it, and grep the log for “Invalid frame dimension”.
  - Narrow it down by adding temporary `assert(x.isFinite && x >= 0)` checks, or `os_log` lines, to every computed frame value. Candidates:
    - `DriveStrip.barWidth(in:)`, the rows width
    - `rowsHeight`, `ClippedHeight`
    - `BayDiagram` (`column` height, `maxHeight * total / largest`, `height * segment.size / … - 1.5`)
    - `CountStepper`
  - Record which expression produces the bad value, and the inputs that cause it.
- [ ] **Step 2: Fix the cause** at its source, for example by clamping a subtraction that can go negative, or guarding a zero divisor. Remove all the temporary instrumentation.
- [ ] **Step 3: Verify.** The two tests pass, and their logs contain no “Invalid frame dimension”. Then, in Task 8's full run, the count must be 0.
